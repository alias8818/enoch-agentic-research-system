## Closeout policy

For each pushed wave:

1. Run full local suite before final push when practical:
   `uv run pytest -q`.
2. Push to `main` only after local checks pass.
3. Wait for exact-SHA GitHub Actions:
   - Code CI
   - Build
   - Public release integrity
   - Release
   - CodeQL
4. Comment on each affected GitHub issue with:
   - exact commit SHA
   - files changed
   - tests run
   - exact-SHA CI URLs/results
   - whether the issue is closed or remains open with remaining scope
5. Update Linear marker/evidence after GitHub writes.

## Risks

- `router.py`, `app.py`, and `supabase_store.py` are large and high-churn; avoid broad rewrites.
- Some findings are readability-only; closing them requires demonstrable source-shape improvement, not runtime behavior changes.
- GitHub CLI auth may expire; public API reads work, but comments/closures/pushes require auth refresh if `gh` returns 401.
- Bare local `pyright` currently reports repo-wide issues not mirrored by the CI gate; rely on configured Code CI for final type gate unless narrowing a specific touched-file error.
